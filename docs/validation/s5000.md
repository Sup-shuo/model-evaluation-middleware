# Moore Threads S5000 validation

Status: full text BBH E2E on the recorded stack, including result publication
and owned-process cleanup.

## Environment

| Component | Observed environment |
| --- | --- |
| Accelerator | MTT S5000, 80 GiB; single-GPU TP1 integration |
| Driver / Runtime | 5.2.0-server / MUSA 5.2.0 |
| Inference Python | Container Python 3.10.12 |
| Backend | vLLM-MUSA 0.28.0; OpenAI-compatible Completions API |
| Inference packages | torch/torch_musa 2.11.0.post2+musa5.2.0; Transformers 5.15.0 |
| Evaluator | Separate lm-eval environment; lm-evaluation-harness 0.4.13.dev0; Transformers 5.14.1 |
| Harness revision | `f4d4b3de3ee6741a7151a9fe74945ee515262f4c` |
| Protocol | Local leaderboard BBH multiple-choice subset, 3-shot, 24 tasks, 5,761 examples |

`device/mthreads` preserves the selected physical-device order through
`MUSA_VISIBLE_DEVICES`; `runtime/musa` supplies the configured toolkit
environment. Inference uses the accelerator. The separate evaluator performs
tokenization, dataset handling, requests, and metric aggregation.

## Exercised coverage

The validated path covers unconverted artifacts and separately materialized
BF16 derivatives. A derived BF16 result does not establish native AWQ/NVFP4
kernel support. Record the effective artifact and any tokenizer override in
the Model configuration when reproducing an evaluation.

Validation covers text BBH; VL model names do not imply that a visual
benchmark was executed. Serving capacity and chunked prefill are explicit
configuration choices, not automatic resource tuning.

## Reproduce the workflow

Use the [portable hardware example](../../examples/hardware/README.md).
Replace its path placeholders, select an available GPU, and prepare the model,
platform-compatible inference stack, evaluator environment, and offline cache.
From the project root:

```bash
python3 -B ./eval-manager validate --system-config examples/hardware/mthreads-s5000.yaml --evaluation-config examples/hardware/bbh.yaml
python3 -B ./eval-manager evaluate --system-config examples/hardware/mthreads-s5000.yaml --evaluation-config examples/hardware/bbh.yaml --smoke
python3 -B ./eval-manager evaluate --system-config examples/hardware/mthreads-s5000.yaml --evaluation-config examples/hardware/bbh.yaml
```

The shared example uses `coder3101/Qwen3.5-4B-heretic`, one GPU, and explicit
CPU offload 0. Smoke checks integration; only the command without `--smoke`
runs the full configured suite. Saved configuration and versions define each
original run; the portable example is a starting configuration, not a lockfile.

Upstream: [vLLM-MUSA](https://github.com/MooreThreads/vllm-musa) and
[torch_musa](https://github.com/MooreThreads/torch_musa).
